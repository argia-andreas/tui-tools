Focus is a contract, not just a border

F1 The selected row stays pinned while you read

Text movement never changes the message. Esc clears selection first, then returns to the list; only Esc in the list leaves the browser. Tab reaches text and named actions. Enter on text does nothing.

F2 Small terminals get the same inspector, full-width

Hide navigation before sacrificing text width. At 80×24, temporarily hide the list; retain queue, identity, row position and Back. Enter temporarily reveals a hidden inspector without changing saved preferences. Resize preserves the logical selection.

F3 Mode and help stay visible

Named focus, a cursor, VISUAL CHAR / VISUAL LINE text and selection counts supplement color. Arrows/Page keys and named palette commands work for non-Vim users. Preserve themes and ASCII mode; do not claim terminal screen-reader support without later validation.

F4 — Copy what was asked for, or explain why not. “Copied 2 lines · body” confirms scope without leaking content. Failures retain the selection. Unconfirmed terminal requests say “Copy requested,” not “Copied.” Truncated previews never pass as full-message copies: offer read-only full-content loading, with size shown, before Y or report copy.

Resend remains explicit, scoped and cancellable

  • S4 Queue DLQ → its source queue, without a picker. Subscription DLQ → explicit same-namespace queue choice. No silent topic fan-out.
  • S5 Configure → prepare exact full message → frozen final review. Cancel starts focused at both stages. Separate Resend copy needs focus + Enter. Visual y never means “yes.”
  • S6 Original deletion defaults off. Turning it on warns of the existing 100-message / 5-second search, temporary locks and delivery-count effects. Back releases a held lock before editing.
  • S7 Confirmed send, confirmed cleanup, cleanup uncertainty and unknown send are different outcomes. Unknown send retains the original; tell the user to check the destination. A result cannot send again.
  • S8 At short/narrow sizes, use a full-width review with visible identity, consequence and Cancel. Hidden confirmations never submit; below 80×24 only cancel/resize/exit are available.

Risks and earliest signals

R1 Clipboard may not be available or verifiable in remote terminals

Earliest signal: copy requests have no confirmation or never reach the user's clipboard. Keep selection, use truthful status and offer manual terminal copy. Transport choice and compatibility proof belong to a later gate.

R2 Partial Vim behavior may surprise experienced users

Earliest signal: users try unsupported operators or use b expecting the sidebar. Show the exact subset in context help; never interpret an unsupported reader key as a broker action.

R3 Wrapped lines or Unicode can make selection ambiguous

Earliest signal: copied text differs from source or resize changes the range. Require logical coordinates, source newline preservation, continuation markers and intact graphemes.

Alternatives considered

A — Local action strip (recommended)

Keep message actions attached to the owning inspector. Slightly less body height, but clearer focus, safety and compact-screen behavior.

B — Workspace-wide action dock

More inspector body space, but actions appear global while their target is one pinned message. Rejected for less obvious ownership; available if the user prefers that tradeoff.

C — Keep the selected-message screen and add yanking there

Less conceptual change, but leaves two reading surfaces and preserves the detour the request aims to remove.

Grounded in the current application

What was checked in the repository

Read the independent app README and current message handling, inspector rendering, selected-message flow, action palette, replay review and offline fixture. No broker access or application run was needed for this design inspection.

  • service-bus-explorer/internal/ui/model.go: Enter opens selected DLQ; Tab can already focus inspector; j/k scroll there; b is global sidebar toggle.
  • service-bus-explorer/internal/ui/view.go: inspector already repeats body, caps preview at 64 KiB, is width-dependent and lacks cursor/selection.
  • service-bus-explorer/internal/ui/selected.go: selected reading view repeats body/properties; same-queue destination is already intentional.
  • service-bus-explorer/internal/ui/review.go and review_view.go: Cancel default, frozen exact-selected review, separate cleanup, pending/release/unknown states and small-screen guards must survive.
  • Current UI has no yank/visual clipboard experience. These mockups are proposals, not evidence that clipboard or resend behavior has been implemented.

Not part of this approval

No architecture, dependencies, clipboard transport, implementation, broker semantics change, full Vim editor, binary export, bulk mutation, cloud auth, MCP, LazyFTP or logs-app changes. Clipboard feasibility, exact rendering budgets and terminal screen-reader validation remain for later gates.
