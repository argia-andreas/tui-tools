Recommendation
Namespace membership is explicit. Azure subscriptions and resource groups help select it; neither alone is the right universal boundary.

Scope first; inclusion second

D1Explicit namespaces; groups are selection aids

Choose one or many namespaces, across resource groups and Azure subscriptions in one explicit tenant/account context. “Select namespaces in this resource group” previews the current list and adds that snapshot. Future namespaces never join automatically.

No global startup scan. Resource-group names and display names alone are not identity. Known namespace entry remains available when broad listing is denied.

D2Reuse Settings → Dashboard inclusion

New cloud environments start in Selected entities mode with nothing selected. The current checkbox list becomes searchable and environment-specific. An explicit All entities in saved namespaces mode includes future entities inside those namespaces; it is never the implicit default.

Both grid and table use the same list. Appearance remains global. Unwatched resources remain browsable only inside the active environment. Scope is not an Azure permission boundary or MCP grant.

Create, apply, save and switch without hidden side effects

D3Create and edit in Settings

New environment → unique name → explicit connection → choose Azure subscriptions to inspect → expand resource groups / select namespaces → review exact members → Apply & use. Duplicate requires a new name; rename preserves inclusion. Applying requires at least one namespace.

Apply changes the session. Existing Save preferences persists all pending settings and the active environment; a clear unsaved banner stays visible until it succeeds. Cancel discards the form; failed Save preserves the session as unsaved. Delete confirms that only local configuration is removed, never Azure resources.

D4Keep active context visible everywhere

Persistent header plus the existing Ctrl+P action palette. Chooser rows show name, namespace count, Azure-subscription count, current marker and attention state. Switching opens the selected environment's Dashboard and never shows old resources under the new name. Last saved active selection returns on restart.

Do not switch during lock acquisition, held review, send or release. Require acknowledgment of terminal action outcomes, including unknown results. Environment names are labels, not production safety enforcement.

Never turn uncertainty into an empty dashboard

D5Start bounded and explain every empty state

No saved cloud environment: Create environment / Add known namespace / Stay offline, without scanning queues. A discovered empty namespace, an empty dashboard inclusion list and a failed discovery each get different copy and recovery actions. Preserve existing local fixture/lab selections under an explicit local environment.

D6Partial access stays partial

Show “2 of 3 namespaces checked”, failing member, last-success time and Retry failed / Details / Edit. Retain observed values as stale (~); unavailable is —, never 0. Count/peek permission failures are distinct from namespace discovery failures.

Call an entity Not found only after a complete successful relevant listing. Otherwise say Could not verify. Keep unresolved saved selections until explicitly forgotten; do not replace them by display-name match. Excluded namespace selections remain recoverable but never counted or queried outside the active scope.

D7Compact terminals keep the decision visible

At 80×24 use full-screen chooser/editor steps; hide the sidebar, not the current environment. Keep selected count, warnings and footer controls visible; full identity uses Details rather than horizontal scrolling. Tab changes panes, arrows/j/k navigate, h/l expand, Space toggles and Enter activates. Printable keys belong to focused inputs; preserve ASCII mode.

Research says combination, not resource group alone

F1The current watchlist cannot constrain discovery

ui/model.go:87–107 discovers before filtering; visible() applies watchlists only to Dashboard. azure/store.go:43–78 pages entities in the fixed emulator namespace. explorer.Resource.Subscription means topic subscription, not Azure subscription. No cloud subscription/RG discovery currently exists.

F2Azure supports both subscription and resource-group listing

Microsoft documents namespace listing across an Azure subscription, irrespective of resource groups, and listing inside one resource group. A group is subscription-qualified; neither dimension describes every environment by itself.

F3Messaging access does not promise broad discovery

Microsoft's resource-scope guidance supports namespace/entity assignments. Known namespace entry avoids requiring broad enumeration but still needs the requested operation's permission and network access. Data roles can include entity-read management actions; do not say they have no management rights.

Risks and limits

R1No live Azure verification. Reference pages do not settle every partially authorized list behavior. A child-scoped grant must not be assumed to make parent-wide listing work. Validate the real permission matrix only after product approval.

R2Snapshot group selection may surprise users expecting dynamic membership. The preview and persistent “New namespaces are not added automatically” explanation make the tradeoff explicit.

R3Browser-rendered product mockups check legibility, not terminal cell capacity, real keyboard handling, Azure access or the usability target. Those remain unverified.

Alternatives rejected

  • RG-only: misses cross-group environments and mixes unrelated namespaces in one group.
  • Azure-subscription-only: still too broad. Namespace names without Azure context hide identity.
  • Live RG wildcard: admits future namespaces without a deliberate choice.
  • Second queue-level scope list: duplicates the existing dashboard inclusion editor.
  • Sidebar-only picker disappears in compact mode; Settings-only switching hides the current operational context. Prefer persistent header and Ctrl+P.

Product boundaries

No deployment, cross-tenant aggregation, shared environments, dynamic tag rules or expanded cloud message-operation permissions. No LazyFTP, logs or MCP changes.
