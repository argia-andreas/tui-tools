## Types & signatures

Illustrative Go declarations below are the proposed public contract. Signatures
have no bodies. Typed intent kinds prevent stringly routed commands; IDs remain
opaque app-owned strings. Types use only standard Go and existing terminal libs.

```go
type IntentKind uint8
const (
    Activate IntentKind = iota + 1
    Select
    Focus
    Dismiss
    Help
    Scroll
)
type Intent struct {
    Kind IntentKind
    ID string
    Delta int // Scroll only; app clamps to its domain/view
}
type Result struct { Consumed bool; Intent *Intent }
type Action struct {
    ID, Label, Keywords, Unavailable string
    Keys []string // single-event tea.KeyMsg.String() values, scoped to owner
    Busy, Dangerous bool
}
type Rect struct { X, Y, W, H int } // absolute, zero-based screen cells
type RegionKind uint8
const (
    ControlRegion RegionKind = iota + 1
    FieldRegion
    RowRegion
    DestinationRegion
    PaneRegion
)
type Region struct { ID string; Kind RegionKind; Bounds Rect }
type Frame struct { Bounds Rect; Lines []string; Regions []Region }
type Style struct {
    Background, Surface, Foreground, Muted, Border, Focus string
    Selection, SelectionText, Warning, Error string
    ASCII bool
}
func Fit(styled string, width int) string
func Panel(title string, body Frame, bounds Rect, focused bool, style Style) Frame
func Overlay(base, foreground Frame, style Style) Frame
func RenderActionBar(actions []Action, bounds Rect, focusID string, style Style) Frame
func HandleActionBar(msg tea.Msg, actions []Action, frame Frame, focusID string) Result
```

Only current authorized actions enter these functions. Unavailable/Busy prevents
activation; no effects/callbacks or tea.Cmd are accepted. Keys are interpreted
only after the owner wins routing; not an always-global keymap. Help shows the
same key metadata. Multi-key reader grammar such as yy stays in local help topics
and reader handlers, not Action.Keys. App IDs are unique within the active scope.

Frames are exact-size lines with absolute, clipped regions. A composed frame
does not expose regions for hidden/covered controls; Overlay keeps only the
foreground's interactive regions. Rows are not focus stops. All rendering and
input geometry is derived from the same current layout function; never reuse a
frame cached before resize/async change. On overlap the more specific visible
body/control region wins over its pane; app bodies cannot overlap shared chrome.

```go
type Palette struct {
    Query, SelectedID string
    Offset int
}
func (p Palette) View(actions []Action, bounds Rect, style Style) Frame
func (p *Palette) Handle(msg tea.Msg, actions []Action, frame Frame) Result

type SurfaceSpec struct {
    ID, Title, CancelID, CancelBlocked string
    Actions []Action
    FocusID string
    FocusOrder []string // current visible body fields and action IDs
    Body Frame // caller's safe styled content and local field/row regions
}
func RenderSurface(spec SurfaceSpec, bounds Rect, style Style) Frame
func SurfaceBodyBounds(bounds Rect) Rect
func HandleSurface(msg tea.Msg, spec SurfaceSpec, frame Frame) Result
func NextFocus(visible []string, current string, backwards bool) string
func HandleNavigation(msg tea.Msg, frame Frame, focusID, selectedID string) Result

type HelpTopic struct { Group, Keys, Description string }
func RenderHelp(actions []Action, topics []HelpTopic, offset int, bounds Rect, style Style) Frame
func HandleHelp(msg tea.Msg, actions []Action, topics []HelpTopic, offset *int, frame Frame) Result
```

Surface mount is determined by its bounds and caller composition: docked uses
RenderSurface in a pane, floating uses Overlay. No mount mode or callback is
needed in SurfaceSpec. Cancel-default confirmation means its initial FocusID is
CancelID; editors instead initially focus a body field. A default button must
never steal Enter from a focused editor. Both blocked close and Cancel use the
current CancelBlocked reason; app also validates cancellation at execution time.
SurfaceBodyBounds reserves the common title/footer/border cells so apps do not
duplicate chrome geometry to lay out their local content. Controls occupy one
footer row; omit secondary actions before clipping, never retain a partial
button's hitbox. Required cancel and validation/safety information take priority;
if those cannot fit, the app's operation gate refuses submission.

Slice 3 implementation clarification: visible Field/Pane targets request Focus,
rows request Select, and explicit controls/destinations request Activate. Tab
traverses visible fields, panes and controls in FocusOrder; panes never activate
on Enter/Space. Arrow traversal belongs to Surface only while a rendered control
is focused. Local field grammar and rename-body scrolling run first. With a
nonempty focus ID, action bars reserve a one-cell `›` marker (`>` in ASCII) for
every complete button so changing focus never shifts geometry. Ordinary workspace
toolbars with an empty focus ID retain their previous density.

Palette's owning app holds open/closed state and return focus. Handle consumes
all input while active. Ctrl+P/Esc/outside left press emits Dismiss, F1 emits Help;
disabled/no-match Enter stays open without Activate. Navigation clamps, typed
queries reset selection, and refreshed actions retain SelectedID if still matched
or choose a safe first result without auto-running it. Fuzzy label matches win,
keyword fallback only if there are no label matches. Query editing: 128 Unicode
runes maximum, Backspace/Ctrl+H removes a rune, Ctrl+U clears; printable text and
spaces accepted, control/format characters rejected, never routed to workspace.

Tab/Shift+Tab cycles the current scope's visible FocusOrder. Palette uses them
to choose result rows rather than workspace focus. Arrows choose palette results;
no optional Ctrl+N/K/P navigation aliases in the shared palette. Ctrl+P only toggles
it closed. App-local reader/Vim aliases remain documented local grammar.

HandleNavigation: pane press requests Focus; data-row press Select; explicit
destination press Activate. Enter requests Activate only for the already selected
row/destination of the focused body; selection bounds/cursor movement and local
Vim keys remain app-owned. Wheel requests Scroll only within the pointed visible
body; pointer release/motion requests nothing. App row IDs must preserve native
identity (file endpoint+entry, message page/sequence, event handle, field path),
not display text/index. Tree disclosure/checkbox regions are explicit controls,
separate from their data rows; clicking a field row does not implicitly copy it.

Help is view-only presentation in the current capture scope. Apps retain one
local help-open flag/offset and underlying draft/review, not a generic modal stack.
F1 toggles this view; Esc/Close returns from help first. Help input is captured,
expiry/completion continues. Pointer help close does not cancel its parent.
Slice 2 adds the small matching HandleHelp function so all consumers share capture
and scroll behavior, without introducing the later Surface implementation. It
clamps the app-owned offset against the same width-dependent wrapped rows as
RenderHelp. Contextual topics precede action metadata, with standalone readable
unavailable reasons. Outside presses are consumed without closing Help.

Application-local integration signatures (not a new public abstraction):

```go
// Each application's existing model owns these operations; identifiers are local.
func (m Model) actions() []terminalui.Action
func (m Model) execute(id string) (tea.Model, tea.Cmd)
func (m Model) handleIntent(intent terminalui.Intent) (tea.Model, tea.Cmd)
func (m Model) interactionFrame() terminalui.Frame
```

FTP/SBX already have execute methods: extend those rather than wrap them in a
second dispatch registry. Logs introduces named execution by factoring existing
Update branches, never by synthesizing shortcuts/re-entering Update. Domain
handlers may retain existing names/signatures; no mandatory uniform internal
model or forced per-domain adapter type. App layout functions can retain current
names; interactionFrame denotes the one current geometry source, not duplication.

## Call stack

### Workspace / palette / button

App Update → process resize/lifecycle → compute authorized actions + current
layout → active help/surface/palette handler, otherwise current control/navigation
handler → consumed Result → local handleIntent → execute or checked local
select/focus operation → existing async commands → domain completion → render.

Shortcut and button/palette use the same execute ID. Labels describe intent:
review-delete opens FTP review; SB receive acquires then reviews, selected-resend
opens its existing configuration/preparation; Logs filters opens the draft.
Shared code neither chooses the domain target nor performs the operation.

### Capturing surface / local editor

App lifecycle first → F1/help override → local editor-owned keystrokes (including
Enter and Logs INSERT Esc) when a body field owns input → shared Surface handles
Tab/visible buttons/close and chrome pointer → local body region request → domain
handler → consume remaining input, never workspace fallback.

The app routes Tab/F1 and explicit action shortcuts before ordinary field text;
local editors retain Ctrl+S/other documented apply grammar. For an already active
Logs INSERT editor, its first Esc goes to the editor, not Surface dismissal.
Ctrl+C keeps each app's current cleanup/ownership semantics. Explicit pointer
Close/Cancel requests cancellation independent of INSERT mode, subject to checks.

Local focus transitions still apply their app-owned effects: Logs leaves INSERT
when Tab leaves its editor pane; SBX clears visual selection/pending grammar when
leaving the reader; FTP retains its remembered file endpoint. Shared traversal
chooses the next visible ID; it does not mutate any of those domain submodes.

The FTP outer workspace also needs explicit picker/wizard outcomes: chooser
Dismiss returns to files, not an unconditional tea.Quit or a synthetic Esc.
Wizard Back calls its existing back/invalidation path, releasing stale tested
candidates. Connection-row click selects only; a labelled Open/Enter opens its
details. Successful wizard tests may still focus Connect; cancel-first applies
to confirmations, not every input form or wizard step.

### Confirmation / busy / async

Common button produces ID → local current review checks expiry, frozen target,
visible safe dimensions, typed authorization and busy permission → existing
operation/release/save function. Async results retain existing generation guards.
Release/motion cannot produce a second activation. Busy/hidden/unavailable
controls cannot activate even if stale visible pixels remain on screen. F1 help
cannot discard authorization, unblock a send, or prevent expiry processing.

SBX specifically factors reviewKey into a checked local intent boundary before
calling operate: operate alone does not enforce phase, expiry, dimensions,
hidden-confirm state or typed delete. Acquisition/preparation cancellation still
reconciles late deliveries; Back to edit resumes only after confirmed release.
FTP named copy/rename/delete/queue operations likewise retain the checks currently
inside key branches. Logs explicit Apply calls the Ctrl+S-equivalent query/apply
operation, not Enter (which can toggle a suggestion, leave INSERT, or remove a
predicate). Explicit Cancel calls cancel-editor, not first-Esc mode switching.

### Rendering

App layout/content/semantic theme → shared Panel/ActionBar/Surface/Palette/Help
→ app positions panes or Overlay composes floating foreground → final frame.
App-specific body regions use exactly the displayed row/field ownership map;
wrapped logical data retains its owner. Safe content is supplied by the app;
Fit/Panel never claim to sanitize arbitrary untrusted provider strings.

Go tests; no claim of screen-reader certification.

## Least confident decisions

1. **Frame/region size versus simplicity:** current-state absolute geometry avoids
   three hit-test implementations; do not grow a scene graph or retain cached
   regions across async/resize. Initial integrations should challenge the boundary.
2. **Surface/editor ownership:** the explicit local-editor-first rule is necessary
   for INSERT/reader semantics. Never use a shared Escape handler or callback to
   guess whether a domain operation can cancel. Public app tests enforce this.
3. **Shared query limit/aliases:** choose 128 runes and core arrows/Tab only for
   consistent behavior. This intentionally removes incidental aliases; document
   it rather than preserve different hidden palettes. Local reader grammar stays.
4. **PTY helper extraction deferred:** no new Python shared module in this design.
   First deliver app behavior using existing scripts, then reassess actual repeated
   lifecycle code; any extraction needs an explicit follow-on design change.
5. **Maintainer ownership:** shared contracts belong to this repository's common
   UI owner (Andreas as reviewer), app-specific effects to each app's code owner.
   A concrete review boundary is sufficient; no new organizational role/system.
